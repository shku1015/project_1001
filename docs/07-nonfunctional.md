# 07. 비기능 요구사항

보안, 개인정보 보호, 로그 보존, 성능, 호환성, 배치처럼 특정 기능에 속하지 않는 요구사항을 정한다.
앞 문서에서 "07 비기능"으로 미뤄 둔 항목은 9절에 모아 어디서 결정했는지 표시했다.

> 이 서비스는 학습 프로젝트다. 실제 운영에 쓴다면 개인정보 보호 관련 법령과 회사 보안 정책을 따로 확인해야 한다. 이 문서의 기간·횟수는 일반적으로 많이 쓰는 값을 기준으로 정했다.

## 1. 계정·인증

### 1.1 비밀번호 규칙 (관리자)

| ID | 규칙 |
|---|---|
| NF-PW-01 | 1~20자. 문자 종류(영문 대문자, 영문 소문자, 숫자, 특수문자)는 1종류만 써도 된다 |
| NF-PW-02 | 현재 비밀번호와 같은 값은 쓸 수 없다 |
| NF-PW-03 | 저장은 BCrypt 단방향 해시. 원문·복호화 가능한 형태로 저장하지 않는다 |

- 아이디 포함 금지, 반복·연속 문자 금지, 변경 주기는 두지 않는다.

- 회원 비밀번호 규칙은 사용자 서비스에서 정한다. 관리자 서비스는 임시 비밀번호만 만든다.
- 학습·테스트 편의를 위해 규칙을 느슨하게 두었다. 실제 운영에 쓴다면 길이(8자 이상), 문자 종류, 아이디 포함·반복 문자 금지, 변경 주기를 추가해야 한다.

### 1.2 임시 비밀번호

| ID | 규칙 |
|---|---|
| NF-TP-01 | 길이는 설정값으로 정한다 (1자 이상, 기본 12자). 문자 종류 조건은 없다. 헷갈리는 문자(`0 O l 1 I`)는 빼고 만든다 |
| NF-TP-02 | 보안 난수 생성기로 만든다 (예측 가능한 난수 금지) |
| NF-TP-03 | 발급 응답에서 한 번만 보여 주고, 로그·감사로그에 남기지 않는다 |

### 1.3 로그인 보호

| ID | 규칙 |
|---|---|
| NF-LG-01 | 비밀번호를 연속 5번 틀리면 계정을 잠근다. 잠금 해제는 다른 관리자만 할 수 있다 (자동 해제 없음) |
| NF-LG-02 | 같은 아이디의 동시 로그인은 허용하지 않는다. 새로 로그인하면 기존 세션과 Refresh Token을 모두 끊는다 |
| NF-LG-03 | 로그인 실패 메시지는 아이디 존재 여부를 알 수 없게 한다 (AUTH BR-01) |
| NF-LG-04 | 2단계 인증(OTP 등), 접속 IP 제한은 이번 범위에서 제외한다 |

### 1.4 로그인 유지 시간

| 대상 | 시간 | 비고 |
|---|---|---|
| ③ 세션 | 요청이 없으면 30분 후 만료 | 요청할 때마다 연장 |
| ①② Access Token | 발급 후 30분 | 연장 없음. 만료되면 재발급 |
| ①② Refresh Token | 발급 후 8시간 | 재발급할 때마다 새 토큰이지만 만료 시각은 **처음 로그인 기준 8시간**을 넘지 않는다 |
| ①② 화면 미사용 | 30분 동안 사용자 조작이 없으면 프론트가 로그아웃 | ③의 세션 30분과 맞추기 위함 |

- 만료 5분 전 "곧 자동 로그아웃됩니다 [연장]" 안내는 이번 범위에서 제외한다.

## 2. 웹 보안

| ID | 항목 | 규칙 |
|---|---|---|
| NF-WS-01 | HTTPS | 운영 환경은 HTTPS만 허용. 개발 환경은 HTTP 허용 |
| NF-WS-02 | 쿠키 (Refresh Token) | `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/api/v1/auth/token` |
| NF-WS-03 | 쿠키 (③ 세션) | `HttpOnly`, `Secure`, `SameSite=Lax`. 로그인 성공 시 세션 ID를 새로 발급 (세션 고정 공격 방지) |
| NF-WS-04 | CSRF (③) | 모든 Form 전송(POST·PUT·DELETE)에 CSRF 토큰을 넣고 서버가 확인한다 |
| NF-WS-05 | CSRF (①②) | API는 `Authorization` 헤더로 인증하므로 CSRF 토큰을 쓰지 않는다. 쿠키를 쓰는 토큰 API(`/auth/token`)는 `SameSite=Strict`와 `Origin` 헤더 확인으로 막는다 |
| NF-WS-06 | XSS | 화면에 출력하는 값은 모두 이스케이프한다 (JSP `<c:out>`, React 기본 동작). 게시글 본문(HTML)은 저장할 때 서버에서 허용 태그만 남기고 나머지는 제거한다 |
| NF-WS-07 | SQL 인젝션 | MyBatis는 `#{}`만 쓴다. 정렬 칼럼처럼 `${}`가 필요한 곳은 허용 목록에 있는 값만 넣는다 |
| NF-WS-08 | 보안 헤더 | `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`. CSP에는 카카오 우편번호 서비스의 스크립트·화면(iframe) 도메인만 외부 예외로 허용한다 (도메인 목록은 개발 시 공식 안내를 확인) |
| NF-WS-09 | CORS | 운영은 같은 도메인에서 서비스해 CORS를 쓰지 않는다. 개발 환경의 React 개발 서버만 허용 목록에 넣는다 |
| NF-WS-10 | 오류 노출 | 오류 응답·화면에 스택 트레이스, SQL, 서버 경로를 보여 주지 않는다 |
| NF-WS-11 | 권한 확인 | 모든 API와 ③ 컨트롤러는 서버에서 권한을 확인한다. 권한 지정이 없으면 기본 거부 ([02-access-model.md](02-access-model.md) 4절) |

## 3. 개인정보 보호

### 3.1 저장

| ID | 규칙 |
|---|---|
| NF-PI-01 | 주민등록번호 같은 고유식별정보는 수집하지 않는다 |
| NF-PI-02 | 비밀번호는 단방향 해시로만 저장한다 (NF-PW-03) |
| NF-PI-03 | 회원의 이름·이메일·휴대폰 번호·생년월일은 **DB에 암호화하지 않고 저장**한다. 대신 접근 권한, 화면 마스킹, 열람 감사로그, 전송 구간 암호화(HTTPS)로 보호한다 |

> **NF-PI-03을 정한 이유**: 이메일·휴대폰 번호를 DB에서 암호화하면 회원 목록의 부분 검색(이름 일부, 휴대폰 뒤 4자리 등)이 불가능해진다. 암호화하려면 검색용 해시 칼럼을 따로 두고 검색을 "정확히 일치"로 바꿔야 한다. 학습 범위와 검색 편의를 고려해 암호화하지 않는다.

### 3.2 열람·반출

| ID | 규칙 |
|---|---|
| NF-PI-11 | 화면·엑셀 마스킹은 마스킹 설정을 따른다 ([04-features/10-masking.md](04-features/10-masking.md)) |
| NF-PI-12 | 개인정보 원문 보기, 수정 화면 진입, 개인정보가 포함된 엑셀 다운로드는 모두 감사로그에 남긴다 |
| NF-PI-13 | 감사로그의 변경 전·후 데이터에는 개인정보를 **마스킹한 값**으로 남긴다. 무엇이 바뀌었는지는 알 수 있되 원문은 남지 않게 한다 |
| NF-PI-14 | 원문 보기 응답은 브라우저에 캐시하지 않는다 (`Cache-Control: no-store`) |
| NF-PI-15 | 애플리케이션 로그(파일 로그)에 개인정보 원문, 비밀번호, 토큰을 남기지 않는다 |

### 3.3 회원 상태별 처리

| ID | 규칙 |
|---|---|
| NF-PI-21 | **휴면 전환**: 마지막 로그인 후 1년 동안 로그인하지 않은 정상 회원을 휴면으로 바꾼다 (매일 배치). 상태 변경 이력에 사유 "장기 미접속"을 남긴다 |
| NF-PI-22 | **탈퇴·삭제 회원 개인정보 보관**: 기간 제한 없이 보관한다. 자동 파기하지 않는다 |

- 실제 운영에 쓴다면 탈퇴 회원 개인정보의 보관 기간과 파기 절차를 관련 법령에 맞게 정해야 한다.

## 4. 첨부파일

| ID | 규칙 |
|---|---|
| NF-FL-01 | 허용 확장자: `jpg` `jpeg` `png` `gif` `pdf` `txt` `hwp` `hwpx` `doc` `docx` `xls` `xlsx` `ppt` `pptx` `zip` |
| NF-FL-02 | 확장자와 실제 파일 형식(MIME)이 맞는지 둘 다 확인한다 |
| NF-FL-03 | 파일은 웹에서 직접 접근할 수 없는 경로에 저장하고, 다운로드는 권한 확인 API로만 한다 |
| NF-FL-04 | 저장 파일명은 무작위 이름(UUID)으로 바꾼다. 원본 파일명은 DB에만 둔다 |
| NF-FL-05 | 저장 경로는 `{기본 경로}/{yyyy}/{MM}/{UUID}` 형태. 기본 경로는 설정 파일로 정한다 |
| NF-FL-06 | 개수·크기 제한은 게시판 설정을 따르고, 서버 전체 요청 크기 상한은 100MB로 둔다 |
| NF-FL-07 | 게시글이 삭제 표시되어도 파일은 지우지 않는다. 삭제 표시된 첨부(`DEL_YN = 'Y'`)의 실제 파일은 30일 후 배치로 지운다 |

**본문 이미지** (게시글 본문에 넣는 이미지. 첨부파일과 별도)

| ID | 규칙 |
|---|---|
| NF-FL-11 | 본문 이미지는 Base64로 본문에 넣지 않는다. 이미지 업로드 API로 먼저 올리고, 받은 URL을 본문에 넣는다 |
| NF-FL-12 | 허용 형식: `jpg` `jpeg` `png` `gif`. 파일당 최대 5MB. 게시판의 첨부 허용 여부·개수와 상관없이 쓸 수 있다 |
| NF-FL-13 | 본문 이미지는 `<img>` 태그로 바로 보여야 하므로 인증 없이 열리는 주소(`/files/images/{UUID}.{확장자}`)로 제공한다. 주소에 추측할 수 없는 UUID를 쓴다. NF-FL-03의 예외다 |
| NF-FL-14 | 글에 연결되지 않은 본문 이미지는 업로드 후 하루가 지나면 배치로 지운다 |

## 5. 로그·데이터 보존

| 대상 | 보존 기간 | 정리 방식 |
|---|---|---|
| 감사로그 `TB_AUDIT_LOG` | 2년 | 월 단위로 지난 데이터 삭제 (배치) |
| 로그인 이력 `TB_ADMIN_LOGIN_HIST` | 1년 | 월 단위 삭제 (배치) |
| Refresh Token `TB_ADMIN_REFRESH_TOKEN` | 만료·폐기 후 7일 | 매일 삭제 (배치) |
| 회원 상태 변경 이력 | 회원과 같이 유지 | 정리하지 않음 |
| 애플리케이션 로그 (파일) | 30일 | 로그 설정으로 자동 삭제 |

- 감사로그는 쌓이는 양이 많으므로 조회 성능을 위한 인덱스와 월별 파티션을 둔다 ([08-architecture.md](08-architecture.md) 7.2, 7.3).
- 조회 화면의 기간 제한(최대 3개월)은 성능 보호용이며 보존 기간과는 별개다.

## 6. 성능

| ID | 항목 | 목표 |
|---|---|---|
| NF-PF-01 | 동시 사용 관리자 | 50명 |
| NF-PF-02 | 목록·상세 API 응답 | 데이터 10만 건 기준 1초 이내 |

| NF-PF-05 | 코드 조회 | 코드 목록을 캐시한다. 코드가 바뀌면 캐시를 비운다 |

- 성능 확인용으로 테스트 데이터에 대량 회원(10만 건)과 감사로그(100만 건)를 넣는 스크립트를 개발 단계에서 따로 만든다.

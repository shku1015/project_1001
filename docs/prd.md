이 문서는 제품 요구사항을 한곳에서 보기 위한 요약이다. 기능·화면·API의 상세는 기존 문서에 있으며 여기서는 링크만 건다.

## 1. 배경과 목적

### 1.1 배경

- 개인·기업 회원이 이용하는 사용자 서비스를 운영하려면, 내부 운영자가 회원·기업·게시판·코드를 관리하고 운영자별 권한을 나눌 수 있는 관리자 서비스가 필요하다.
- 사용자 서비스는 아직 없으며, 이번에는 관리자 서비스만 만든다.

### 1.2 목적

| 구분 | 목적 |
|---|---|
| 제품 | 내부 운영자가 회원·기업·게시판·코드·메뉴·관리자 권한을 한 시스템에서 관리한다. 개인정보는 권한·마스킹·감사로그로 보호한다 |
| 학습 | 같은 화면 명세를 **React(토큰)**, **JSP + API(토큰)**, **JSP SSR(세션)** 세 방식으로 구현해 화면 구조(SPA / MPA / SSR)와 인증 방식(토큰 / 세션)을 비교한다 |

## 2. 사용자

내부 운영자만 로그인한다. 운영자 유형은 역할로 나눈다 ([01-overview.md](01-overview.md) 3절).

| 사용자 | 하는 일 | 주로 쓰는 메뉴 |
|---|---|---|
| 슈퍼관리자 | 시스템 전체 관리, 최초 설정 | 전체 |
| 시스템관리자 | 메뉴·코드·관리자·역할·권한·마스킹 설정, 감사로그 확인 | 시스템관리, 관리자관리 |
| 회원운영자 | 회원·기업 문의 응대, 상태 변경, 개인정보 확인 | 회원관리 |
| 콘텐츠운영자 | 공지·FAQ 작성, QnA·1:1문의 답변, 게시글 관리 | 게시판관리 |
| 조회전용 | 모니터링, 감사 | 허용된 메뉴의 조회 |

### 3.2 제외

- 사용자 서비스 화면 전체
- 기업 담당자 로그인, 데이터 범위 권한(특정 기업만 관리)
- 결제·정산·통계 대시보드, 외부 연동(SSO, 메일·문자 발송)
- 2단계 인증, 접속 IP 제한, 모바일 화면
- 탈퇴 회원 복구 기능, 배치 관리 화면

## 5. 우선순위

| 우선순위 | 범위 | 이유 |
|---|---|---|
| **P0 (MVP)** | 로그인·내 정보, 코드, 메뉴, 역할·권한·관리자, 기업정보, 사용자관리 (세 프론트 모두) | 권한 구조와 회원 관리가 있어야 관리자 서비스로 쓸 수 있다 |
| **P1** | 게시판·게시글(답글, 본문 이미지, 첨부, 게시판별 메뉴), 마스킹 설정, 감사로그 조회 | 콘텐츠 운영과 개인정보 관리 고도화 |
| **P2** | 배치(휴면 전환, 정리 작업), 성능 데이터 검증, 공통 E2E 테스트 | 운영 안정화와 학습 결과 정리 |

## 7. 가정과 제약

- 학습 프로젝트이며 동시 사용 관리자는 50명 이하로 본다.
- 사용자 서비스가 없으므로 회원·게시글 데이터는 테스트 데이터로 준비한다.
- 비밀번호 규칙, 개인정보 보관 기간 등은 학습 편의를 위해 느슨하게 정했다. 실제 운영 시 법령·보안 정책을 다시 확인해야 한다 ([ADR-0016](adr/0016-relaxed-password-policy.md), [ADR-0008](adr/0008-personal-data-storage.md)).
- 전자정부프레임워크 5.0.2를 쓴다 ([ADR-0017](adr/0017-egovframe-5-0-2.md)).

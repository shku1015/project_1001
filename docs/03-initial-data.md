# 03-1. 초기 데이터

시스템을 처음 띄울 때 넣을 데이터와 개발·테스트용 데이터를 정의한다.
SQL 파일은 개발 단계에서 DDL과 함께 이 문서를 기준으로 만든다.

| 구분 | 내용 | 정의 위치 |
|---|---|---|
| 운영 필수 | 코드 그룹·상세코드 | [03-domain-erd.md](03-domain-erd.md) 5절 |
| | 메뉴 트리, 권한 | 05 화면 명세 (메뉴 트리 = 메뉴관리 초기 데이터) |
| | 역할, 역할-권한 | 이 문서 1절, [02-access-model.md](02-access-model.md) 6절 |
| | 최초 관리자 | 이 문서 2절 |
| | 마스킹 설정 | [04-features/10-masking.md](04-features/10-masking.md) 4절 |
| 테스트용 | 관리자, 기업, 회원, 게시판, 게시글 | 이 문서 3절 |

> 테스트용 데이터는 개발·테스트 환경에만 넣고 운영 환경에는 넣지 않는다.
> 모든 테스트 데이터는 가상의 값이다. 이메일은 `example.com`, 휴대폰 번호는 `010-0000-xxxx` 형식을 쓴다.

## 1. 역할

| 역할 코드 | 역할명 | 시스템 역할 | 권한 |
|---|---|---|---|
| `SUPER_ADMIN` | 슈퍼관리자 | Y | 권한 체크 예외 (R1) |
| `SYSTEM_ADMIN` | 시스템관리자 | N | [02-access-model.md](02-access-model.md) 6절 매트릭스 |
| `MEMBER_OPERATOR` | 회원운영자 | N | 〃 |
| `CONTENT_OPERATOR` | 콘텐츠운영자 | N | 〃 |
| `VIEWER` | 조회전용 | N | 〃 |

## 2. 최초 관리자 (운영 필수)

| 로그인 아이디 | 이름 | 역할 | 비고 |
|---|---|---|---|
| `admin` | 최초관리자 | `SUPER_ADMIN` | 임시 비밀번호(`PWD_TEMP_YN = 'Y'`). 첫 로그인 시 비밀번호 변경 |

초기 비밀번호 값은 문서에 적지 않고, 설치 시 환경 변수로 넣는다 ([08-architecture.md](08-architecture.md) 8절).

## 3. 테스트용 데이터

### 3.1 관리자

역할별 권한 동작을 확인하기 위한 계정이다. 비밀번호는 모두 같은 테스트용 값으로 한다 (개발 환경 설정에 둔다).

| 로그인 아이디 | 이름 | 역할 | 상태 | 확인 목적 |
|---|---|---|---|---|
| `t_super` | 테스트슈퍼 | `SUPER_ADMIN` | 사용 | 슈퍼관리자가 2명일 때는 회수 가능, 한 명을 사용중지하면 남은 한 명은 보호(R3) |
| `t_system` | 테스트시스템 | `SYSTEM_ADMIN` | 사용 | 메뉴·코드·관리자·역할 관리 |
| `t_member` | 테스트회원운영 | `MEMBER_OPERATOR` | 사용 | 회원·기업 관리, 개인정보 원문 보기 |
| `t_content` | 테스트콘텐츠 | `CONTENT_OPERATOR` | 사용 | 게시판·게시글 관리 |
| `t_viewer` | 테스트조회 | `VIEWER` | 사용 | 조회만 가능, 버튼 숨김 확인 |
| `t_multi` | 테스트다중역할 | `MEMBER_OPERATOR`, `CONTENT_OPERATOR` | 사용 | 다중 역할 권한 합집합 |
| `t_norole` | 테스트역할없음 | (없음) | 사용 | "사용 가능한 메뉴가 없습니다" 안내 |
| `t_locked` | 테스트잠김 | `VIEWER` | 잠금 | 잠금 계정 로그인 차단, 잠금 해제 |
| `t_disabled` | 테스트중지 | `VIEWER` | 사용중지 | 사용중지 계정 로그인 차단 |

### 3.2 기업

| 기업명 | 사업자등록번호 | 대표자 | 상태 | 소속 회원 수 | 확인 목적 |
|---|---|---|---|---|---|
| (주)테스트상사 | 1000000001 | 김대표 | 정상 | 4 | 기본 조회, 삭제 불가 확인 |
| 테스트솔루션(주) | 1000000002 | 이대표 | 정상 | 3 | |
| 테스트물산 | 1000000003 | 박대표 | 정상 | 2 | |
| 테스트유통(주) | 1000000004 | 최대표 | 정지 | 1 | 정지 기업, 소속 기업 선택 목록에서 제외 |
| 테스트빈기업 | 1000000005 | 정대표 | 정상 | 0 | 소속 회원이 없어 삭제 가능 |

### 3.3 회원

개인 회원 10명, 기업 회원 10명을 만든다. 상태와 가입 경로를 고루 섞는다.

| 로그인 아이디 | 구분 | 소속 기업 | 상태 | 가입 경로 | 비고 |
|---|---|---|---|---|---|
| `p_user01` ~ `p_user05` | 개인 | - | 정상 | 사용자 서비스 | 기본 조회 |
| `p_user06` | 개인 | - | 휴면 | 사용자 서비스 | 휴면 해제 |
| `p_user07` | 개인 | - | 정지 | 사용자 서비스 | 정지 해제, 상태 이력 1건 |
| `p_user08` | 개인 | - | 탈퇴 | 사용자 서비스 | 수정·상태 변경 불가 |
| `p_user09` | 개인 | - | 정상 | 관리자 등록 | 임시 비밀번호 상태 |
| `p_user10` | 개인 | - | 정상 | 관리자 등록 | 삭제 표시됨 (목록에서 안 보임) |
| `c_user01` ~ `c_user04` | 기업 | (주)테스트상사 | 정상 3, 탈퇴 1 | 사용자 서비스 | 탈퇴 회원도 소속 회원으로 집계 |
| `c_user05` ~ `c_user07` | 기업 | 테스트솔루션(주) | 정상 | 사용자 서비스 2, 관리자 등록 1 | |
| `c_user08` ~ `c_user09` | 기업 | 테스트물산 | 정상 1, 정지 1 | 사용자 서비스 | |
| `c_user10` | 기업 | 테스트유통(주) | 정상 | 사용자 서비스 | 정지 기업 소속 |

- 이름: `테스트` + 번호 (예: 테스트01). 마스킹 확인을 위해 2자·3자·4자 이름을 섞는다.
- 이메일: 로그인 아이디 + `@example.com`
- 휴대폰 번호: `0100000` + 4자리 번호 (예: `01000000001`)
- 엑셀 다운로드와 페이징 확인을 위해, 위 20명 외에 정상 상태 개인 회원 `bulk_0001` ~ `bulk_0100` 100명을 더 넣는다.

### 3.4 게시판과 게시글

| 게시판 코드 | 게시판명 | 유형 | 게시판별 관리 메뉴 | 게시글 |
|---|---|---|---|---|
| `NOTICE` | 공지사항 | 공지 | 생성 | 관리자 글 5건 (상단 고정 1건, 숨김 1건) |
| `FAQ` | 자주 묻는 질문 | FAQ | 생성 | 관리자 글 6건 (분류 2개에 3건씩) |
| `QNA` | 묻고 답하기 | QnA | 생성 | 아래 참고 |
| `INQUIRY` | 1:1 문의 | 1:1문의 | 생성 | 회원 글 3건 (답변대기 2, 답변완료 1) |
| `FREE` | 자유게시판 | 일반 | 생성 안 함 | 회원 글 5건, 댓글·대댓글 포함, 첨부 1건 |

**QnA 게시글 (답글 구조 확인용)**

| 원글 | 답글 구성 | 답변 상태 |
|---|---|---|
| 회원 질문 1 | 답글 없음 | 답변대기 |
| 회원 질문 2 | 관리자 답글 1개 | 답변완료 |
| 회원 질문 3 | 관리자 답글 → 회원 재답글 | 답변대기 |
| 회원 질문 4 | 관리자 답글 → 회원 재답글 → 관리자 재답글 (깊이 3) | 답변완료 |
| 회원 질문 5 | 관리자 답글 1개, 원글은 삭제됨 | "삭제된 글입니다" 표시 확인 |

- FAQ 분류용 코드 그룹 `FAQ_CATEGORY`(일반 코드)를 만든다: `ACCOUNT` 계정, `SERVICE` 서비스 이용.

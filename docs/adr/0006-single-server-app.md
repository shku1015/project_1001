# ADR-0006. 서버 애플리케이션 1개, URL 접두어로 프론트 구분

- 상태: 승인
- 날짜: 2026-10-04
- 관련 문서: [08-architecture.md](../08-architecture.md) 1절

## 맥락

API, ② JSP 페이지, ③ JSP SSR, ① React 빌드 결과, 배치를 어디서 제공할지 정해야 했다. 권한·코드 캐시는 변경 즉시 반영되어야 한다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **서버 1개** | 캐시가 한곳. 같은 도메인이라 CORS 불필요. 배포 단순 | 보안 필터 체인을 경로별로 나눠야 함. 한 앱이 커짐 |
| API 서버와 SSR 서버 분리 | 역할이 분명 | 한쪽에서 권한을 바꾸면 다른 쪽 캐시를 비울 방법(분산 캐시, 메시지)이 필요. CORS 설정 필요 |

## 결정

- 서버 애플리케이션 1개가 모두 제공한다.
- 프론트는 URL 접두어로 구분한다: `/react/**`, `/jsp/**`, `/ssr/**`, API는 `/api/v1/**`, 본문 이미지는 `/files/images/**`.
- 메뉴 테이블에는 접두어 없는 경로를 저장하고 각 프론트가 접두어를 붙인다.
- 코드는 Maven 모듈로 나눈다: `admin-core`(업무), `admin-web`(실행 앱), `admin-react`.

## 결과

- 좋은 점: 한 서버에서 세 프론트를 나란히 띄워 비교할 수 있다. 메모리 캐시(Caffeine)로 충분하다.
- 감수할 점: 서버를 여러 대로 늘리면 캐시 공유와 배치(`@Scheduled`) 중복 실행 방지가 필요해진다. 지금은 1대를 전제로 한다.

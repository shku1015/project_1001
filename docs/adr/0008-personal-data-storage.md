# ADR-0008. 개인정보 저장·보관 방식

- 상태: 승인
- 날짜: 2026-10-04
- 관련 문서: [07-nonfunctional.md](../07-nonfunctional.md) 3절

## 맥락

회원의 이름·이메일·휴대폰 번호·생년월일을 저장한다. 처음 ERD 초안에서는 "이름·이메일·휴대폰 번호를 DB에 암호화"를 제안했다. 그런데 회원 목록에는 이름 일부, 휴대폰 뒤 4자리 같은 부분 검색이 필요하다. 탈퇴·삭제 회원의 개인정보를 언제까지 둘지도 정해야 했다.

## 검토한 대안

**저장 방식**

| 대안 | 장점 | 단점 |
|---|---|---|
| 칼럼 암호화 (AES) | DB가 유출되어도 원문 보호 | 부분 검색 불가 |
| 암호화 + 검색용 해시 칼럼 | 보호와 정확히 일치 검색 | 부분 검색 불가, 칼럼·로직 증가 |
| **암호화하지 않음 + 접근 통제** | 부분 검색 가능, 단순 | DB 접근 권한 관리에 의존 |

**탈퇴·삭제 후 보관**

| 대안 | 판단 |
|---|---|
| 30일 후 자동 파기 (1차 제안) | 사용자가 채택하지 않음 |
| **기간 제한 없이 보관** | 사용자 결정 |

## 결정

- 개인정보는 **DB에 암호화하지 않고** 저장한다. 권한(`PRIVACY`), 화면·엑셀 마스킹, 열람 감사로그, HTTPS로 보호한다.
- 감사로그의 변경 전·후 데이터에는 개인정보를 **마스킹한 값**으로 남긴다.
- 탈퇴·삭제 회원의 개인정보는 **기간 제한 없이 보관**하고 자동 파기하지 않는다.
- 고유식별정보(주민등록번호 등)는 수집하지 않는다. 비밀번호는 BCrypt 해시로만 저장한다.

## 결과

- 좋은 점: 회원 검색이 편하고 구조가 단순하다.
- 감수할 점: DB 자체가 유출되면 원문이 노출된다. 탈퇴 회원 정보가 계속 쌓인다. **실제 운영에 쓴다면 관련 법령에 맞춰 암호화와 보관 기간을 다시 정해야 한다.**

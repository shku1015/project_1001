# ADR-0002. 슈퍼관리자는 권한 체크 예외로 처리

- 상태: 승인
- 날짜: 2026-10-04
- 관련 문서: [02-access-model.md](../02-access-model.md) 5절 R1·R2

## 맥락

시스템 전체를 관리하는 슈퍼관리자가 필요하다. 새 메뉴가 생겨도 슈퍼관리자는 바로 접근할 수 있어야 하고, 실수로 슈퍼관리자의 권한이 빠져 시스템이 잠기면 안 된다.

검토 중 외부 의견으로 "코드에 예외를 두지 말고, 모든 권한이 매핑된 역할로 처리하는 편이 RBAC 원칙에 맞다"는 제안이 있었다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **권한 체크 예외 (슈퍼관리자면 통과)** | 새 메뉴에 자동으로 접근. 권한 데이터가 꼬여도 잠기지 않음 | 권한 체크 코드에 예외 분기가 생김. 권한 매트릭스에 슈퍼관리자가 보이지 않음 |
| 모든 권한을 매핑한 시스템 역할 | 권한 체크가 한 가지 방식뿐. 매트릭스에 그대로 보임 | 권한이 생길 때마다 슈퍼관리자 역할에 자동 매핑하는 규칙이 필요. 매핑이 빠지면 접근 불가 |

## 결정

**권한 체크 예외**로 처리한다.

- 슈퍼관리자 역할은 시스템 역할(`SYSTEM_YN = 'Y'`)로 표시하고 수정·삭제할 수 없다.
- 사용 중인 슈퍼관리자가 1명이면 그 관리자의 사용중지·역할 회수를 막는다 (R3).

## 결과

- 좋은 점: 메뉴·권한 데이터 상태와 상관없이 슈퍼관리자는 항상 들어올 수 있어 복구 수단이 된다.
- 감수할 점: 권한 평가기에 슈퍼관리자 분기가 들어간다. 권한 화면에서 슈퍼관리자 행은 "모두 있음"으로 따로 그려야 한다. 대안(전체 매핑 역할)으로 바꾸려면 새 ADR이 필요하다.

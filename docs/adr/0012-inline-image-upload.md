# ADR-0012. 본문 이미지는 업로드 후 URL 삽입

- 상태: 승인
- 날짜: 2026-10-04
- 관련 문서: [07-nonfunctional.md](../07-nonfunctional.md) NF-FL-11~14, [06-api/05-board.md](../06-api/05-board.md) API-PST-13

## 맥락

게시글 에디터는 Quill로 정했다. 사용자는 이미지를 **본문에도 넣고, 첨부파일로도** 올릴 수 있어야 한다고 정했다. Quill은 기본으로 이미지를 Base64 문자열로 본문에 넣는다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| Base64로 본문에 삽입 (Quill 기본) | 구현 없음 | 이미지 몇 장으로 본문이 수 MB. 목록·저장·감사로그가 무거워짐 |
| **업로드 API로 올리고 URL 삽입** | 본문이 가벼움. 이미지를 파일로 관리 | 업로드 API, 연결·정리 로직 필요 |

이미지 주소의 인증도 검토했다. `<img>` 태그는 토큰 헤더를 실을 수 없고, 사용자 서비스에서도 보여야 한다.

## 결정

- 본문 이미지는 업로드 API로 먼저 올리고 받은 URL을 본문에 넣는다. Base64 삽입은 막는다.
- 이미지 주소는 인증 없이 열리는 `/files/images/{UUID}.{확장자}`로 제공한다. 추측할 수 없는 UUID를 쓴다.
- jpg·png·gif, 파일당 5MB. 게시판의 첨부 설정과 무관하게 쓸 수 있다.
- 게시글 저장 시 본문의 이미지를 글에 연결하고, 하루 동안 연결되지 않은 이미지는 배치로 지운다.
- 첨부파일은 기존 방식(권한 확인 다운로드)을 그대로 쓴다.

## 결과

- 좋은 점: 본문이 가볍고, 이미지와 첨부의 용도가 분명하다.
- 감수할 점: 본문 이미지는 주소만 알면 누구나 볼 수 있다 (첨부파일 보호 규칙 NF-FL-03의 예외). ③ SSR용 세션 업로드 경로가 따로 필요하다 (ADR-0005).

# 01. 서비스 개요

## 1. 목적

사용자 서비스에 가입한 개인·기업 회원과 서비스 운영 데이터(코드, 게시판 등)를 내부 운영자가 관리하는 **관리자 서비스**를 구축한다.

- 운영자는 회원과 기업 정보를 조회·관리하고, 게시판 콘텐츠를 운영한다.
- 메뉴와 권한을 DB로 관리해, 코드 배포 없이 관리자별 접근 범위를 바꿀 수 있게 한다.
- 개인정보 열람과 주요 변경 작업은 기록으로 남긴다.

## 2. 범위

### 2.1 포함 (In Scope)

| 영역 | 기능 | 설명 |
|---|---|---|
| 회원 운영 | 기업정보관리 | 기업 등록·조회·수정·삭제, 소속 기업회원 확인. 승인 절차 없음, 소속 회원이 있으면 삭제 불가 |
| | 사용자관리 | 개인 회원, 기업 회원 조회·상태 변경 |
| 콘텐츠 운영 | 통합게시판관리 | 게시판 설정(게시판 생성·옵션 관리)과 게시글 운영(공지 작성, QnA 답글, 게시글·댓글·첨부 관리). 게시판은 사용자 서비스에도 노출되어 회원이 사용한다 |
| 시스템 설정 | 코드관리 | 서비스 전반에서 쓰는 그룹코드/상세코드 |
| | 메뉴 동적관리 | 관리자 화면 메뉴 트리 |
| 관리자 운영 | 관리자관리 | 관리자 계정 생성·잠금·해제 |
| | 관리자 권한관리 | 메뉴 × 액션 단위 권한 |
| | 관리자 역할관리 | 권한 묶음, 관리자에게 부여 |
| 공통 | 로그인/로그아웃, 내 정보 | 관리자 인증 |
| | 감사로그 | 개인정보 열람, 주요 데이터 변경 기록과 조회 화면, 관리자 로그인 이력 조회 |
| | 개인정보 마스킹 설정 | 개인정보 항목별 화면·엑셀 마스킹 켜고 끄기 |

### 2.2 제외 (Out of Scope)

- 사용자 서비스(회원 가입, 로그인, 게시판 이용 등 사용자 화면)
- 기업 담당자의 관리자 서비스 로그인 (내부 운영자만 사용)
- 결제, 정산, 통계 대시보드 (추후 검토)
- 외부 시스템 연동(SSO, 메일·SMS 발송 등) — 필요 시 별도 기획
- 데이터 범위 권한 (관리자별로 특정 기업 데이터만 관리하는 기능)

> 사용자 서비스는 아직 없으므로, 회원·게시글 등의 데이터는 관리자 서비스에서 테스트 데이터로 준비한다.

## 3. 사용자 (관리자 유형)

관리자 유형은 **역할(Role)** 로 표현한다. 아래는 초기 역할 예시이며, 역할은 관리자 화면에서 추가·수정할 수 있다.

| 역할 | 설명 | 주요 접근 범위 |
|---|---|---|
| 슈퍼관리자 | 시스템 전체 관리 | 모든 메뉴, 모든 액션 (권한 체크 예외) |
| 시스템관리자 | 시스템 설정 담당 | 메뉴·코드·관리자·권한·역할 관리 |
| 회원운영자 | 회원 응대 담당 | 기업정보, 사용자관리 (개인정보 열람 포함 여부는 별도 부여) |
| 콘텐츠운영자 | 게시판 운영 담당 | 통합게시판관리 |
| 조회전용 | 모니터링, 감사 | 허용된 메뉴의 조회만 |

## 4. 용어집

| 용어 | 영문 | 정의 |
|---|---|---|
| 사용자 서비스 | User Service | 개인·기업 회원이 이용하는 서비스. 이번 범위 밖 |
| 관리자 서비스 | Admin Service | 내부 운영자가 사용하는 관리 시스템. 이번 범위 |
| 회원 / 사용자 | User | 사용자 서비스에 가입한 사람. 개인 회원과 기업 회원으로 나뉜다 |
| 개인 회원 | Personal User | 기업에 소속되지 않은 회원 |
| 기업 회원 | Corporate User | 기업에 소속된 회원 |
| 기업 | Company | 기업 회원이 소속된 조직 |
| 관리자 | Admin | 관리자 서비스에 로그인하는 내부 운영자 |
| 메뉴 | Menu | 관리자 화면의 메뉴 항목. 트리 구조이며 DB로 관리한다 |
| 액션 | Action | 메뉴에서 할 수 있는 작업 종류 (조회, 등록, 수정, 삭제, 엑셀, 개인정보열람) |
| 권한 | Permission | 메뉴 × 액션 한 쌍. 예: "사용자관리-수정" |
| 역할 | Role | 권한의 묶음. 관리자에게 부여한다 |
| 데이터 범위 권한 | Data Scope Permission | 같은 메뉴 안에서 접근할 수 있는 데이터 행을 제한하는 권한 (예: 사용자관리에서 특정 기업의 회원만 보기). **이번 범위에서 제외** |
| 게시판별 메뉴 권한 | Per-board Menu Permission | 게시판마다 별도 메뉴(`POST_{게시판 코드}`)를 두고, 그 메뉴에 주는 일반 권한(메뉴 × 액션). 데이터 범위 권한이 아니다 |
| 그룹코드 / 상세코드 | Code Group / Code | 상태값·구분값 등 공통 코드. 그룹코드 아래에 상세코드가 있다 |
| 게시판 마스터 | Board Master | 게시판 하나의 설정(유형, 댓글·첨부 허용 등) |
| 게시글 | Post | 게시판에 작성된 글 |
| 감사로그 | Audit Log | 누가, 언제, 무엇을 열람·변경했는지 남기는 기록 |
| 마스킹 | Masking | 개인정보 일부를 `*`로 가려 표시하는 것 |

## 5. 프론트엔드 구성

같은 기능을 프론트엔드 3종으로 구현한다(학습 목적). 화면 명세는 하나이며, 세 프론트가 같은 동작을 해야 한다.

| 구분 | 방식 | 서버와의 통신 |
|---|---|---|
| ① React | SPA | REST API (JSON) |
| ② JSP + API | JSP 화면 + JavaScript | REST API (JSON, AJAX) |
| ③ JSP SSR | Spring MVC 서버 렌더링 | Form 전송, 서버가 HTML 생성 |

인증은 학습 목적으로 두 방식을 모두 쓴다. ① React와 ② JSP + API는 토큰(JWT), ③ JSP SSR은 세션이다 ([04-features/09-auth.md](04-features/09-auth.md) 1.1).

# 04-09. 로그인·내 정보 (공통)

## 1. 개요

관리자 로그인, 로그아웃, 본인 정보 관리. 메뉴와 권한이 필요 없고 로그인만 필요하다.

- 관련 테이블: `TB_ADMIN`, `TB_ADMIN_LOGIN_HIST`, `TB_ADMIN_REFRESH_TOKEN`, `TB_ADMIN_ROLE`, `TB_ROLE_PERMISSION`, `TB_MENU`

## 1.1 인증 방식

학습 목적으로 **세션 방식과 토큰 방식을 둘 다** 구현한다. 프론트마다 하나씩 쓴다.

| 프론트 | 인증 방식 | 로그인 상태 보관 |
|---|---|---|
| ① React | **토큰** (JWT) | Access Token: 브라우저 메모리. Refresh Token: HttpOnly 쿠키 |
| ② JSP + API | **토큰** (JWT) | Access Token: 페이지의 JavaScript 메모리. Refresh Token: HttpOnly 쿠키 |
| ③ JSP SSR | **세션** | 서버 세션 + 세션 쿠키 |

> ②와 ③은 같은 JSP 화면을 토큰과 세션으로 각각 구현해 비교한다.
> ①과 ②는 같은 토큰 방식을 SPA와 여러 페이지(MPA) 구조에서 각각 다뤄 비교한다.

- **REST API(`/api/...`)는 토큰으로만 인증한다.** ①②만 API를 쓰고, 둘 다 토큰 방식이기 때문이다.
- **JSP SSR 화면(③)은 세션으로만 인증한다.** ③은 API를 호출하지 않고 컨트롤러가 Service를 직접 호출한다.
- 로그인 처리 규칙(BR-01~BR-06)과 권한 체크는 두 방식이 같은 Service를 쓴다. 인증 방식은 "누가 요청했는지 확인하는 방법"만 다르다.

### 토큰 방식

| 토큰 | 형태 | 유효 시간 | 쓰임 |
|---|---|---|---|
| Access Token | JWT (관리자 ID, 발급·만료 시각) | 30분 | API 요청마다 헤더로 보냄 |
| Refresh Token | 임의 문자열. DB에는 해시만 저장 | 8시간 | Access Token이 만료되면 새로 발급받을 때 씀 |

- Access Token에는 권한을 넣지 않는다. 서버가 요청마다 관리자 ID로 최종 권한을 확인한다. 그래야 권한 변경이 다음 요청부터 바로 반영된다 ([08-role.md](08-role.md) BR-09).
- Refresh Token은 한 번 쓰면 새 토큰으로 바꿔 준다 (재사용 방지). 이미 쓴 토큰이 다시 오면 그 관리자의 모든 Refresh Token을 폐기한다.
- 로그아웃하면 Refresh Token을 폐기한다. Access Token은 만료될 때까지 남지만 30분으로 짧게 둔다.
- Refresh Token 쿠키는 토큰 API 경로(`/api/v1/auth/token`: 재발급, 로그아웃)에만 보내도록 범위를 좁힌다 (쿠키 설정은 [07-nonfunctional.md](../07-nonfunctional.md) NF-WS-02).

**② JSP + API에서 토큰을 쓸 때 주의할 점**

②는 화면을 옮길 때마다 페이지를 새로 불러오므로, 메모리에 둔 Access Token이 사라진다.

- 페이지를 열면 먼저 토큰 재발급 API를 호출해 Access Token을 받고, 그다음 데이터 API를 호출한다.
- 재발급에 실패하면(Refresh Token 만료·폐기) 로그인 화면으로 보낸다.
- JSP 페이지 요청 자체는 브라우저 이동이라 토큰 헤더를 실을 수 없다. 그래서 ②의 JSP 페이지는 데이터가 없는 껍데기로 두고 서버에서 인증하지 않는다. 데이터와 권한은 모두 API에서 확인한다.
- Access Token을 `sessionStorage`에 두면 페이지 이동마다 재발급하지 않아도 되지만, 스크립트 공격(XSS)에 노출될 수 있어 쓰지 않는다.

### 세션 방식 (③)

- 로그인하면 서버 세션에 관리자 ID를 넣는다. 세션 유효 시간은 BR-08의 자동 로그아웃 시간과 같다.
- ③의 Form 전송은 CSRF 토큰으로 방어한다 ([07-nonfunctional.md](../07-nonfunctional.md) NF-WS-04).

### 공통

- 관리자를 사용중지하거나 비밀번호를 초기화하면 그 관리자의 세션과 Refresh Token을 모두 끊는다 ([06-admin.md](06-admin.md) BR-09). 이를 위해 세션을 DB에 저장해 관리자별로 찾아 끊을 수 있게 한다 (Spring Session JDBC, [08-architecture.md](../08-architecture.md) 2.1).

## 2. 기능 목록

| ID | 기능 | 설명 |
|---|---|---|
| AUTH-01 | 로그인 | 로그인 아이디와 비밀번호로 로그인 |
| AUTH-02 | 로그아웃 | 로그인 상태 종료 |
| AUTH-03 | 비밀번호 변경 강제 | 임시 비밀번호로 로그인했으면 비밀번호 변경 화면으로 보낸다 |
| AUTH-04 | 내 메뉴·권한 조회 | 로그인 후 내 메뉴 트리와 최종 권한 목록을 받는다 (메뉴·버튼 노출용) |
| AUTH-05 | 내 정보 조회·수정 | 이름, 이메일, 휴대폰 번호, 부서 수정 |
| AUTH-06 | 비밀번호 변경 | 현재 비밀번호 확인 후 새 비밀번호로 변경 |
| AUTH-07 | 토큰 재발급 | Refresh Token으로 새 Access Token과 Refresh Token 발급 (토큰 방식만) |

## 3. 비즈니스 규칙

| ID | 규칙 |
|---|---|
| BR-01 | 아이디가 없을 때와 비밀번호가 틀렸을 때 같은 메시지를 보여 준다 ("아이디 또는 비밀번호가 올바르지 않습니다") |
| BR-02 | 비밀번호가 틀리면 실패 횟수를 1 올린다. 연속 5번 틀리면 계정을 잠근다 ([07-nonfunctional.md](../07-nonfunctional.md) NF-LG-01) |
| BR-03 | 로그인에 성공하면 실패 횟수를 0으로 되돌리고 마지막 로그인 일시를 남긴다 |
| BR-04 | 잠금·사용중지 계정은 비밀번호가 맞아도 로그인할 수 없다. 잠금이면 "관리자에게 잠금 해제를 요청하세요"라고 안내한다 |
| BR-05 | 성공·실패와 상관없이 모든 로그인 시도를 `TB_ADMIN_LOGIN_HIST`에 남긴다 |
| BR-06 | 역할이 없거나 사용 가능한 메뉴가 하나도 없으면 로그인은 되지만 "사용 가능한 메뉴가 없습니다"를 보여 준다 |
| BR-07 | 비밀번호 변경 시 현재 비밀번호와 같은 값은 쓸 수 없다 |
| BR-08 | 30분 동안 요청·조작이 없으면 자동 로그아웃한다 ([07-nonfunctional.md](../07-nonfunctional.md) 1.4) |
| BR-09 | 내 정보에서 로그인 아이디와 역할은 바꿀 수 없다 |
| BR-10 | 같은 아이디의 동시 로그인은 허용하지 않는다. 새로 로그인하면 기존 로그인(세션·토큰 모두)을 끊는다 ([07-nonfunctional.md](../07-nonfunctional.md) NF-LG-02) |

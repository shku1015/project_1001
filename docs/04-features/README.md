## 2. 문서 구성

각 기능 문서는 같은 순서로 작성한다.

1. 개요: 기능의 목적과 관련 테이블
2. 권한: 기능별로 필요한 액션
3. 기능 목록: 기능 ID, 기능명, 설명
4. 비즈니스 규칙: 규칙 ID(`BR-xx`)와 내용
5. 상태 전이: 상태값이 있는 경우
6. 감사로그: 기록 대상
7. 미결 사항

## 3. 공통 규칙

모든 기능에 적용한다. 기능 문서에서는 다른 점만 적는다.

### 3.1 목록

| 항목 | 규칙 |
|---|---|
| 페이지 크기 | 10 / 20 / 50 중 선택. 기본 20 |
| 기본 정렬 | 등록일시 내림차순 (최신순). 기능별로 다르면 기능 문서에 적는다 |
| 검색 | 기간 검색은 등록일시 기준. 텍스트 검색은 부분 일치 |
| 삭제된 데이터 | 삭제 표시(`DEL_YN = 'Y'`)된 데이터는 목록에 보이지 않는다 |
| 코드값 표시 | 코드 칼럼(`_CD`)은 코드관리의 상세코드명으로 표시한다 |

### 3.2 등록·수정

- 필수 항목이 빠지면 저장하지 않고 항목별로 오류를 안내한다.
- 서버에서 다시 검증한다. 프론트 검증만 믿지 않는다.
- 중복 불가 항목(로그인 아이디, 사업자등록번호, 코드 등)은 저장 시 서버에서 확인한다.
- 수정할 때 다른 관리자가 먼저 수정했으면 저장하지 않고 다시 조회하도록 안내한다 (`MOD_DT` 비교).

### 3.3 삭제

- 삭제 전 확인 메시지를 띄운다.
- 삭제 방식(실제 삭제 / 삭제 표시 / 상태 변경)은 [03-domain-erd.md](../03-domain-erd.md) 1.4를 따른다.

### 3.4 엑셀 다운로드

- 현재 검색 조건의 결과 전체를 내려받는다 (페이지와 무관).
- 한 번에 최대 10,000건. 넘으면 검색 조건을 좁히도록 안내한다.
- 개인정보는 마스킹 설정의 "엑셀 마스킹" 값을 따른다 ([10-masking.md](10-masking.md)). 마스킹을 끈 항목도 `PRIVACY` 권한이 있어야 원문으로 내려받는다.
- 다운로드할 때마다 감사로그를 남긴다.

### 3.5 개인정보 표시

- 개인정보(이름, 이메일, 휴대폰 번호, 생년월일)의 마스킹 여부는 항목별로 설정한다 ([10-masking.md](10-masking.md)). 기본값은 모두 마스킹이다.
- 마스킹된 항목은 `PRIVACY` 권한이 있는 관리자가 상세 화면에서 "원문 보기"를 누르고 사유를 입력하면 원문을 볼 수 있다.
- 원문 보기 사유는 코드 그룹 `PRIVACY_REASON`에서 고른다. "기타"를 고르면 직접 입력해야 한다.
- 원문 보기는 한 번에 회원 한 명 단위로 하고, 매번 감사로그를 남긴다.

### 3.6 감사로그

- 각 기능 문서의 "감사로그" 절에 적힌 작업은 [03-domain-erd.md](../03-domain-erd.md)의 `TB_AUDIT_LOG`에 기록한다.
- 기록에 실패하면 원래 작업도 취소한다 (같은 트랜잭션).

### 3.7 권한 없음

- 권한이 없는 기능의 버튼은 비활성으로 보여 준다 ([05-ia-screens.md](../05-ia-screens.md) 4.2).
- URL로 직접 접근하거나 API를 직접 호출해도 서버에서 막는다 ([02-access-model.md](../02-access-model.md) 4절).

# 04-08. 관리자 역할관리

## 1. 개요

권한을 묶어 역할을 만들고, 역할에 들어갈 권한을 정한다. 역할은 관리자관리에서 관리자에게 부여한다.

- 관련 테이블: `TB_ROLE`, `TB_ROLE_PERMISSION`, `TB_PERMISSION`, `TB_MENU`, `TB_ADMIN_ROLE`
- 보호 규칙은 [02-access-model.md](../02-access-model.md) 5절을 따른다.

## 2. 권한

| 기능 | 액션 |
|---|---|
| 역할 목록·상세 조회, 역할을 가진 관리자 보기 | `READ` |
| 역할 등록, 역할 복사 | `CREATE` |
| 역할 정보 수정, 권한 설정 | `UPDATE` |
| 역할 삭제 | `DELETE` |

## 3. 기능 목록

| ID | 기능 | 설명 |
|---|---|---|
| ROL-01 | 역할 목록 조회 | 검색 조건: 역할 코드, 역할명, 사용 여부. 역할별 관리자 수 표시 |
| ROL-02 | 역할 상세 조회 | 역할 정보, 권한 표, 이 역할을 가진 관리자 목록 |
| ROL-03 | 역할 등록 | 역할 코드, 역할명, 설명 입력 |
| ROL-04 | 역할 복사 | 기존 역할의 권한을 그대로 가진 새 역할 만들기 |
| ROL-05 | 역할 정보 수정 | 역할명, 설명, 사용 여부 수정 |
| ROL-06 | 권한 설정 | 메뉴 트리 × 액션 체크박스 표에서 권한을 고르고 저장 |
| ROL-07 | 역할 삭제 | 부여된 관리자가 없을 때만 삭제 |

## 4. 비즈니스 규칙

| ID | 규칙 |
|---|---|
| BR-01 | 역할 코드는 영문 대문자, 숫자, `_`만 쓰고 중복될 수 없다. 등록 후 바꿀 수 없다 |
| BR-02 | 시스템 역할(`SYSTEM_YN = 'Y'`, 슈퍼관리자)은 수정·삭제·권한 설정을 할 수 없다 (R2) |
| BR-03 | 권한 표에서 `READ`가 아닌 액션을 체크하면 같은 메뉴의 `READ`가 자동으로 체크된다. `READ`를 해제하면 같은 메뉴의 다른 액션도 해제된다 |
| BR-04 | 본인이 가진 역할은 수정할 수 없다. 슈퍼관리자는 예외 |
| BR-05 | 본인이 갖지 않은 권한은 체크할 수 없다 (R5). 슈퍼관리자는 예외 |
| BR-06 | 관리자에게 부여된 역할은 삭제할 수 없다 (R6). 역할 삭제는 실제 삭제이며 권한 매핑도 함께 지운다 |
| BR-07 | 역할을 사용 안 함으로 바꾸면 그 역할의 권한은 최종 권한 계산에서 빠진다. 관리자에게 부여된 상태는 유지한다 |
| BR-08 | 사용 안 함 역할은 관리자에게 새로 부여할 수 없다 |
| BR-09 | 권한 변경은 해당 역할을 가진 관리자의 다음 요청부터 반영된다 |

## 5. 감사로그

| 작업 | 기록 내용 |
|---|---|
| 등록, 복사, 정보 수정, 삭제 | 변경 전·후 데이터 |
| 권한 설정 | 추가·제거된 권한 목록 |

## 6. 미결 사항

| No | 내용 | 제안 |
|---|---|---|
| 1 | 역할을 사용 안 함으로 바꿨을 때 최종 권한에서 빼는 것(BR-07)이 맞는지 | 뺌 |
